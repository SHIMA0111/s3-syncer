# s3-syncer

`s3-syncer` は、AWS S3 バケット間のデータ移行を行うための高性能な CLI ツールです。AWS プロファイルを使用したクロスアカウントコピーをサポートしており、拡張性を考慮してヘキサゴナルアーキテクチャで構築されています。

## 主な機能

- **クロスアカウント対応**: 独立した Source (転送元) と Destination (転送先) のプロファイルを指定することで、異なる AWS アカウント間のバケットでシームレスにコピーが可能です。
- **高パフォーマンス**: ワーカープールを使用した並列ファイルコピーにより、スループットを最大化します。
- **大容量ファイル対応**: AWS SDK Manager を介したマルチパートアップロードを使用して、大きなファイルを自動的に処理します。
- **進捗状況の追跡**: 検出されたファイル数とコピー済みファイル数をリアルタイムのプログレスバーで表示します。
- **選択的コピー**: プレフィックスによるオブジェクトのフィルタリングが可能です。

## インストール

### ソースからビルド

要件: Go 1.18 以降

```bash
git clone https://github.com/SHIMA0111/s3-syncer.git
cd s3-syncer
go build -o s3-syncer ./cmd
```

## 使い方

### 基本的な使い方

デフォルトアカウント内で、あるバケットから別のバケットへコピーする場合:

```bash
./s3-syncer --src-bucket my-source-bucket --dst-bucket my-dest-bucket
```

### クロスアカウントコピー

アカウント間でコピーする場合、`~/.aws/credentials` または `~/.aws/config` にプロファイルが設定されていることを確認してください。

```bash
./s3-syncer \
  --src-profile profile-a \
  --dst-profile profile-b \
  --src-bucket source-bucket \
  --dst-bucket dest-bucket \
  --region us-west-2
```

### 並列数の制御とチューニングガイド

`--workers` フラグで同時実行数を調整できます。Goroutine は非常に軽量なため、マシンリソース（CPU/メモリ）的には数千の並列実行も可能ですが、**AWS S3 の API レート制限**やネットワーク帯域がボトルネックになることがあります。

#### 推奨設定の目安

| 環境スペック | 推奨ワーカー数 | 備考 |
|------------|-------------|------|
| **ローカル PC / 低帯域** | 10 - 50 | デフォルト(10)は安全な設定です。 |
| **一般的なサーバー (2-4 vCPU)** | 50 - 200 | ほとんどのユースケースで十分な速度が出ます。 |
| **高性能サーバー (8+ vCPU, 10Gbps+)** | 300 - 1000+ | 大量の小ファイルを転送する場合に有効です。 |

#### 注意点: S3 API レート制限について
S3 はプレフィックスごとに **PUT/COPY/POST/DELETE で秒間 3,500 リクエスト**、**GET/HEAD で秒間 5,500 リクエスト** のガイドラインがあります。
ワーカー数を過剰に上げると（例: 2000以上）、AWS から `503 Slow Down` エラーが返され、バックオフ処理により逆に全体の転送速度が低下する可能性があります。

```bash
# 高スペックマシンでの実行例
./s3-syncer --src-bucket source --dst-bucket dest --workers 300
```

### フラグ一覧

| フラグ | 説明 | デフォルト値 |
|------|-------------|---------|
| `--src-bucket` | 転送元の S3 バケット名 (必須) | |
| `--dst-bucket` | 転送先の S3 バケット名 (必須) | |
| `--src-profile` | 転送元アカウントの AWS プロファイル | default |
| `--dst-profile` | 転送先アカウントの AWS プロファイル | default |
| `--prefix` | コピー対象キーのプレフィックスフィルタ | "" |
| `--region` | AWS リージョン | us-east-1 |
| `--workers` | 同時実行ワーカー数 | 10 |

## アーキテクチャ

このプロジェクトは **ヘキサゴナルアーキテクチャ (Ports and Adapters)** パターンを採用しています。

- **Core (Domain)**: `internal/core` に配置。ビジネスロジックとインターフェース (`ports`) を定義しています。
- **Adapters**: `internal/adapters` に配置。S3 (`adapters/s3`) や CLI (`adapters/cli`) の実装を含みます。

この設計により、テストが容易になり、将来的な拡張（例：ローカルファイルシステム、Google Cloud Storage、Azure Blob Storage への対応など）も `Storage` インターフェースを実装するだけで簡単に行えます。
